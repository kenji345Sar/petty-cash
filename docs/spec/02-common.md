# 共通仕様 — 小口・業者で共通する概念

> 小口タブ・業者タブの両方で使う概念をここに一本化する（重複説明を避けるため）。
> 各タブ固有の点は [petty-cash.md](./03-petty-cash.md) / [vendor.md](./04-vendor.md) に書く。

## 1. 金種

紙幣・硬貨の種類（10000 / 5000 / 1000 / 500 / 100 / 50 / 10 / 5 / 1 円）ごとの枚数。合計金額は「額面 × 枚数」の合計で、どの画面でも同じ計算をする。

```
1万円 × 3枚 = 30,000円
千円  × 5枚 =  5,000円
合計         = 35,000円
```

金種は2つの場面で使う。

| 場面 | 意味 | 画面 |
|---|---|---|
| 入出金の金種表 | 取引に含まれる紙幣・硬貨の内訳 | 入力フォームの「金種表」ボタン → 金種を入れて確定すると、合計が金額欄にセットされる |
| 有高チェック | 実際に数えた枚数 | 「有高」ボタン → 金種を入れて保存（→ 2. 有高チェック） |

- 金種表はキャンセルすると、金額欄を変えずに入力フォームへ戻る。
- 取引に金種がある場合、出納帳から金種内訳を表示できる。
- 定義: `frontend/src/shared/denomination.ts`（`DENOM_ITEMS`）

## 2. 有高チェック

実際の現金を金種で数え、帳簿の金額と照合して差額を出す操作。

```
有高チェックを保存
  ↓
チェック結果を記録（実数・帳簿・差額）
  ↓
差額 ≠ 0 なら調整取引（Adjustment）を自動で作り、帳簿を実数に合わせる
  ↓
バッグのチェックなら、バッグの金額も実数に更新する
```

| 数えるもの | 帳簿の金額 | 差額があるとき |
|---|---|---|
| 小口（小口タブ） | 小口残高（業者残高は含めない） | 小口取引に調整を記録 |
| 両替金バッグ / 売上バッグ | バッグの金額 | 業者取引に調整を記録し、バッグの金額を実数に更新 |
| 準備バッグ | バッグの金額 | 記録のみ（調整取引は作らない） |

- チェック結果は、取引と同じく出納帳に番号付きで並ぶ。
- 後から修正できる。修正すると差額を計算し直して記録を更新するが、調整取引は作り直さない。

## 3. 赤伝（逆仕訳）

過去取引を打ち消す仕組み。**元取引は削除せず、反対方向の取引を末尾に追加する**（追記型）。
履歴・監査のため、訂正しても元の記録を残すのが目的。

実装: `ReversePettyCashTransactionUseCase` / `ReverseVendorTransactionUseCase`、逆転ロジックは Domain の `CreateReversal`。

### 逆転ルール（小口・業者共通）

| 元取引 | 赤伝で追加される取引 | 金額 |
|---|---|---|
| 入金 (Deposit) | 出金 (Withdrawal) | 元と同額 |
| 出金 (Withdrawal) | 入金 (Deposit) | 元と同額 |
| 調整 (Adjustment, ≥0) | 出金 (Withdrawal) | 元と同額 |
| 調整 (Adjustment, <0) | 入金 (Deposit) | **絶対値** |

> 実装: `PettyCashTransaction.CreateReversal` / `VendorTransaction.CreateReversal`（switch式で上記4パターンを判定）

### 重要な性質

- 赤伝は**新しい連番・新しい行**として時系列の末尾に積まれる。元取引やその後の行の `balance` は書き換えない。
- 入金の赤伝は「出金」になるため、**残高が不足していると失敗する**（`EnsureCanWithdraw`）。過去の入金を取り消したくても、その分が既に使われていると赤伝できない。
- 摘要の既定値は `#<元の番号>の修正（赤伝）`。

### 二重赤伝（仕様未確定）

同一取引IDに対して複数回赤伝を打つことの可否は **仕様未確定**（2026-06-24 時点）。

- 現実装: Domain に「赤伝済み」状態を持たないため防止していない
- 運用上問題が発生した場合: Domain への赤伝済みフラグ追加または Application での重複チェックを追加する

> ⚠️ 業者の赤伝には固有の制約がある（バッグ状態を戻さない）。[vendor.md](./04-vendor.md#5-赤伝修正) を参照。

## 4. 残高（running balance）

各取引が「その時点の残高」を**取引行ごとに保持**する。出納帳の残高列はこの値をそのまま表示する。

**設計方針**: 残高は金庫(Safe)ではなく**取引(Transaction)が持つ**。金庫が持つのは現在残高のスナップショット（`vendorBalance` / `pettyCashBalance`）のみ。

**計算タイミング**: 書き込み時に1回だけ計算して保存する（読み取り時に再計算しない）。
実装: `BalanceService.AssignBalanceAsync`
- 直前の残高を「全件合計」ではなく**最新1行の `balance` を読む**（`ORDER BY created_at DESC, id DESC LIMIT 1`）。
- そこに今回の増減（出金は `-amount`、それ以外は `+amount`）を足して新しい残高とする。

**読み取り**: QueryService は保存済みの `balance` をそのまま返すだけ（再計算なし）。

> ES+CQRS を入れて Read Model 経由で残高を読むようにしても、「残高は取引行に保存」という事実は変わらない。詳細は [docs/event-sourcing/](../event-sourcing/README.md)。

## 6. 取引種別

| 種別 | 意味 | 残高への影響 | 発生する場面 |
|---|---|---|---|
| 入金（Deposit） | 金庫にお金が入る | +金額 | 入出金登録、バッグ入金、赤伝 |
| 出金（Withdrawal） | 金庫からお金が出る | −金額 | 入出金登録、バッグ移動・引渡、赤伝 |
| 調整（Adjustment） | 有高チェックの差額 | +金額（符号付き。マイナスなら減る） | 有高チェックで差額が出たとき（→ 2.） |

出納帳には、取引のほかに有高チェックの記録（「有高」）も並ぶ。有高チェックの記録は残高を変えない。
